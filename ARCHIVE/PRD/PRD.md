# Riddle 产品需求文档（PRD）

> 版本：v0.2（2026-09-21） | 状态：已审议通过，作为 SPEC 与技术验证线依据
> 文档依据：`ANALYSIS/` 四个收敛讨论（共识 C1–C11、T1–T4、M1–M4、W1–W3）+ 圆周旅迹拆解
> 读者：产品、设计、工程、Agent 开发

## 1. 背景与问题

旅行规划是一个**低频、高客单价、高失败成本**的决策场景。用户的核心困境不是信息不够，而是信息到行动之间的转化断裂。经盘点（`RAWIDEAS/TravelPlanElementsMindmap.km`），痛点归为五类：

| 编号 | 痛点 | 典型场景 |
|------|------|----------|
| A1 | 不知道去哪玩 | 有假期有预算，没有目的地 |
| A2 | 知道点位不知道怎么游玩 | 收藏了一堆攻略，串不成行程 |
| A3 | 知道行程但事项遗漏/链路断裂 | 酒店没订、景点没预约、交通衔接算错 |
| A4 | 酒店选择困难 | 不熟悉城市，不知道住哪个片区 |
| A5 | 怕遗漏，"安全感焦虑" | 事无巨细都要管，越到出发越慌 |

现有方案（地图、OTA、内容社区、AI 规划工具）各自只解决一段，用户在"收藏—规划—预订—准备"之间反复横跳，用 excel 和收藏夹勉强缝合（详见 `ANALYSIS/04_competitor_matrix.md`）。

## 2. 产品定位

**Riddle 是一个旅行规划 Copilot**：像 Riddle 的日记本一样，用户往里"倒入"任何旅行相关素材与想法，它将其转化为**有实效性的结构化旅行方案**；用户按方案做完准备清单，即大概率收获一段顺利旅行。

- **主战场痛点**：A2 + A5（共识 M 系列；A1 是 LLM 最拥挤的低差异赛道，A4 依赖数据生态，均后置）
- **双护城河**（共识 W1）：
  1. **任意混合素材输入 → 结构化方案**（攻略文本/订单/链接/零散想法 → 候选池 → 方案图）——竞品仅支持链接地点提取，无混合输入管线
  2. **行前准备 checklist 执行闭环**（预订/物品/信息三类，可勾选、带相对截止）——全行业缺位
- **质量叙事**（共识 W1/W3）：不说"反幻觉"，说"**实时核验 + 物流可行性 + 查不到就留空给你填**"。与 iMean 的区隔：iMean 核验单个 POI 的事实，Riddle 核验**整条行程链的语义闭环**（时间连续、空间衔接、约束满足）。
- **商业哲学**：不追求一站式闭环（机酒用户自己订最信，共识 C10）；留空位与推荐位在用户规模形成后转化为 OTA 导购收入（C10 衍生商业线索）。

## 3. 目标与非目标

### 3.1 本期目标（MVP）
- 跑通"素材输入 → 候选池 → 方案图 → 多轮迭代 → checklist 派生 → READY"的完整链路
- 用真实案例（四川六日环线）验证方案质量不低于头号对标（圆周旅迹）
- 验证 LLM + Jev 双模型架构下决策层（意图/槽位/校验/传播）的可靠性

### 3.2 非目标（本期明确不做）
目的地发现（A1 深度探索）、住宿实时房态/价格与交易闭环、境外目的地（共识 P1）、外部时间 API（日出类，C10 留空策略）、预算账本（C1）、多人协作（C3）、行中与复盘（C2）、API 直订（checklist 仅半闭环跳链+提示档）。

## 4. 用户与场景

目标人群直接对标圆周旅迹核心用户（用户画像专项暂缓，随 demo 后访谈验证）：**J 人/规划控型自由行用户**，习惯从小红书/公众号"抄作业"，有把攻略转化为个人行程的强需求，对工具的结构化能力和信息可信度敏感。

核心场景（四川六日环线，即 gold truth 案例）：用户国庆计划成都+九寨黄龙+峨眉乐山六日（含返程七日），手头有小红书攻略若干、初步想去的点位清单。她需要：搞清地理可行性 → 排出每日动线 → 确定住哪 → 知道要抢哪天的票、预约什么、带什么 → 出发前逐项勾完，安心出发。

## 5. 核心概念与信息架构

（详见 `ANALYSIS/01_deliverable_information_architecture.md`，此处为产品视角摘要）

- **语义层**：旅行方案 = Node-Edge-Node 图 + Events。Node = POI/AOI；Edge = 七类路由；Event = 点位游览/消费/就餐或一段交通。无悬挂约束仅作用于方案图；**候选池**是图外的合法暂存区（攻略解析出的点位先入池，评估后转正或弃置）。锚点分住宿、场站两类。
- **四阶段状态机**：需求明确 → 规划中 → 准备中 → READY，阶段可逆，流转由机械检查自动执行（槽位门槛/checklist 清空），无需用户确认。
- **展示层**：行程总览、每日日程、地图视图、住宿建议（片区级）、大交通建议（留空+时限提醒+回填，仅驾车段自动）、准备清单、信息附录。
- **确定性分级**：L0 事实（数据源直取，模型禁入）/ L1 决策（Jev 判定或 LLM 生成+Jev 校验）/ L2 生成（LLM+抽检+免责标注）。
- **变更与回滚**：每次输入 = 图操作；传播半径 R1 局部/R2 当日/R3 跨日由 Jev 判定，低置信度转异步 HITL；操作日志（event sourcing）支持回滚。

## 6. 功能需求

### 6.1 意图与交互（详见 `ANALYSIS/02_intent_taxonomy_and_slots.md`）

**持续输入原则**：素材与需求可在任意阶段、任意时刻注入，不存在“一次性输入后锁定”的环节。每次输入都触发完整循环：意图识别 → 图操作/槽位更新 → 语义校验 → 传播；方案随输入持续演化，READY 后亦可修改（阶段自动降级）。

八类意图多标签识别：I1 素材注入、I2 探索咨询（场景化：候选池空→降级引导，池丰富→池内问答）、I3 约束声明、I4 方案变更、I5 确认决策、I6 进度汇报、I7 信息回填、I8 元操作。槽位冲突=后输入优先+显式确认；状态变更型意图（I5/I6）采用更高置信度阈值。澄清单轮最多 1–2 问，按“阻塞度×信息增益”选题。

### 6.2 需求优先级（P0=MVP 必须，P1=MVP 内增强，P2=二期）

| 编号 | 需求 | 痛点 | 优先级 |
|------|------|------|--------|
| F1 | 任意素材解析入候选池（文本攻略优先，订单/链接其次） | A2 | P0 |
| F2 | 候选池→方案图生成（每日动线+交通衔接+片区住宿建议） | A2 | P0 |
| F3 | 多轮对话迭代（增删换移，含传播与异步 HITL） | A2/A3 | P0 |
| F4 | 语义闭环校验（时间连续/空间衔接/约束满足，生成后必跑） | A3 | P0 |
| F5 | checklist 派生与勾选（三类；信息类三要素：查什么/预期/流程指导） | A5 | P0 |
| F6 | 阶段流转与 READY 判定 | A5 | P0 |
| F7 | 留空与回填机制（时间/班次/票价类） | A3 | P0 |
| F8 | 回滚与操作历史 | A3 | P1 |
| F9 | 地图视图（高德，画布/列表） | A2 | P1 |
| F10 | 开销记录（Event 级，总览只读聚合） | —— | P1 |
| F11 | OTA 导购位 | 商业 | P2 |

## 7. 体验原则

- **澄清先行**：拿不准先问，单轮不超过 2 问；模糊值（"五一前后 5 天"）合法，不强制精确。
- **权衡透明**：AI 的调整须附带理由（缓冲推理、取舍逻辑），借鉴圆周旅迹"先交底再问取舍"的问法与来源引用块（用于 L2 内容区）。
- **用户掌控**：状态变更可确认、操作可回滚、AI 不静默覆盖。
- **视觉方向**：扁平极简，Notion 式黑白风（UI 线后置，先做低保真 UE）。

## 8. 成功指标

- **北极星候选**：checklist 勾选完成率（执行价值）；方案编辑保留率（生成质量）
- **过程指标**：澄清轮次（过低=擅自假设）、I5/I6 误锁定率、传播 HITL 率、候选池提取率（方案对池内点位的利用度）
- **验证方式**：gold truth 1–2 个真实 case（四川六日环线为首个，覆盖"城市群"类）；demo 产出后补用户访谈验证 A2/A5 优先级假设（共识 M4）

## 9. 依赖与约束

- 高德（Amap）MCP/API：地理信息与地图唯一底座；跨城仅驾车+测地线，火车/飞机数据无源（LAB01 已验证）→ 对应留空回填设计
- Jev API（已持有 key）：决策层——意图/槽位/完整性/指代/澄清选题/传播半径
- LLM：素材理解、文案生成、工具调用
- 现有资产：`amap-skills/`、`KB/amap-webservice`、`LAB/lab01`、`learnPiAgent`（PiAgent 源码）

## 10. 风险与对策

| 风险 | 等级 | 对策 |
|------|------|------|
| A2/A5 优先级未经用户验证（访谈推迟） | 中 | PRD 显式标注为假设；demo 后访谈校准，预留转向空间 |
| 动态信息失真（闭店/改时间，行业主失效模式） | 高 | L0 数据源直取+Jev 校验+留空回填；叙事即"实时核验" |
| 状态变更误操作（I5/I6 误判锁定） | 中 | 高置信度阈值+显式确认+回滚 |
| 圆周旅迹快速跟进（其迭代与池能力已超预期） | 中 | 护城河压注在混合素材管线与 checklist 深度；持续跟踪 |
| OTA 导购与 OTA 竞品的数据/竞合关系 | 低（远期） | 二期设计，保持导流中立性 |
| 国庆等高峰场景的时效敏感（抢票/堵车） | 中 | 时限提醒进 checklist；缓冲推理透明化 |
