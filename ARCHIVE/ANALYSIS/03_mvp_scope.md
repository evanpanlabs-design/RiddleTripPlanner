# 讨论 3：MVP 范围切割

> 状态：🟢 已达共识 | 当前版本：v1.1（2026-09-21，P1/P2 确认，全部事项关闭）
> 讨论目标：基于讨论 1（交付物）与讨论 2（意图/槽位）的共识，切出第一版的范围。

## 1. 切割逻辑（v1 定稿）

- **痛点维度**：A2（知道点位不知道怎么玩）+ A5（怕遗漏）优先。注意：A2/A5 的优先级排序在 PRD 中标注为**待验证假设**——用户访谈推迟至 demo 之后（共识 M4），PRD 风险章节需显式声明。
- **阶段维度**：聚焦 `规划中 → 准备中 → READY`。"需求明确"阶段只做轻量承接，不做目的地发现。
- ~~地理维度~~ **已撤销（共识 M2）**：不以地理空间限界。任何行程——单城市、一城+周边、城市群/环线——都拆解回 Event/NEN 基础框架：多地区输入先解析为多个地区，各自捞取 POI/玩法转化为 Event，再做事件连接。**视野以 Event 为基础排布旅程，GIS 信息只负责提供事实可靠性。** 实际边界由数据源能力自然形成：
  - 跨城 Edge：高德仅支持**驾车 + 测地线连接**两种方式；
  - 飞机/高铁/火车/轮船等交通方式：**留待用户手动查询并填写**（C10 留空哲学的延伸）；
  - 境外目的地：高德数据体系外，MVP 不支持（推论 P1，待用户确认）。

## 2. MVP 范围内（v1 定稿）

### 2.1 意图覆盖
- **完整支持**：I1、I3、I4（含 C7 传播）、I5、I6、I7、I8
- **场景化支持 I2（共识 M1）**：以候选池状态为路由条件——候选池空/稀少时用户问探索类问题 → 归为目的地发现（MVP 外，礼貌降级引导）；候选池丰富但用户仍问 → 说明方案对候选池的**提取率不足**，属"基于候选池的玩法问答"（MVP 内，且触发方案质量自查）。Jev 判定池状态并路由。

### 2.2 区块覆盖
- 全量：B1 行程总览、B2 每日日程、B3 地图视图、B6 准备清单（灵魂区块）、B7 信息附录
- B4 住宿简化版：片区建议 + 理由，不接实时房态/价格
- B5 大交通简化版（v1 修正）：跨城段仅驾车/测地线可自动给出里程耗时；其余交通方式 = 留空 + 购票时限提醒 + 用户回填（推论 P2，待用户确认）

### 2.3 闭环深度
- checklist 执行方式：MVP 只承诺"可半闭环（跳链/唤起）+ 仅提示"，API 直订不做
- 时间锚定信息：LLM 推理 + 留空回填，不接外部时间 API

### 2.4 checklist 分类（共识 M3，v1 定稿为三类）
- **预订类**：机票/酒店/门票/餐厅等
- **物品类**：行李与证件（证件并入物品，不单列）
- **信息类**：**结构化信息查询任务**——websearch 大概率无法回答"某小店是否需要线上排队取号"这类长尾事实，必须引导用户自查。每个信息类任务项须包含三要素：**要查什么 / 预期查到什么 / 查询结果对后期流程的指导**（例：查到"需提前 3 天公众号取号"→ 自动生成新的预订类前置任务）

### 2.5 技术范围
高德 MCP/API、event sourcing、Jev 决策点全量、LLM 生成 + Jev 校验循环。

## 3. 明确不做（v1）

目的地发现（A1 深度探索）、住宿实时房态/价格与交易闭环（二期，与 OTA 商业化一并设计）、外部时间 API、境外目的地（P1 待确认）、预算账本、多人协作、行中与复盘。

## 4. 验证与度量（v1 定稿）

- **Gold truth（共识 M4）**：0-1 阶段仅需 1–2 个真实 case，覆盖两类行程——**单城市内** 与 **城市群游**。访谈验证推迟至 demo 产出之后。
- **北极星候选**：checklist 勾选完成率、方案编辑保留率
- **过程指标**：澄清轮次、I5/I6 误锁定率、传播 HITL 率、**候选池提取率**（共识 M1 衍生：池内点位落图比例，方案质量的核心信号）

## 5. 开放问题裁决记录

- **M1 ✅**：I2 边界场景化——按候选池状态路由（空/稀→目的地发现，丰富→池内问答+提取率信号）。
- **M2 ✅**：撤销地理维度切割，以 Event 为基础排布旅程；跨城仅驾车+测地线自动，其他交通用户手动查填。
- **M3 ✅**：checklist 三类（预订/物品含证件/信息）；信息类三要素（查什么/预期结果/流程指导）。
- **M4 ✅**：gold truth 1–2 个（单城市+城市群），访谈延后至 demo 后。

### 遗留推论（✅ 已确认 2026-09-21）
- P1 ✅：境外目的地 MVP 不支持（高德数据体系外的自然边界）。
- P2 ✅：B5 大交通在 MVP 的实际形态 = 留空 + 时限提醒 + 用户回填（仅驾车段可自动出里程耗时）。
