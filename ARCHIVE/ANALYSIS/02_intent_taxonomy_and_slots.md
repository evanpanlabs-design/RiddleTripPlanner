# 讨论 2：意图 taxonomy 与槽位体系（Jev 决策层设计）

> 状态：🟢 已达共识 | 当前版本：v1（2026-09-21，T1–T4 全部裁决，讨论 2 关闭）
> 讨论目标：定义 Jev 在意图解析、路由、澄清上的决策空间——意图分类体系、槽位体系、阶段流转的槽位门槛、澄清策略。承讨论 1：每个意图最终映射为图操作、状态流转、checklist 更新或内容生成。

## 1. 设计约束（承前共识）

- Jev 输出空间必须预定义为封闭 schema → 意图体系是**封闭枚举 + 置信度**，不留开放文本输出。
- 低置信度 → 异步 HITL（共识 C7/C10 哲学）：不阻塞，挂起待用户下轮处理。
- 用户输入是任意素材 → 意图识别**多标签**：一段话可同时包含素材注入 + 约束声明 + 方案变更。
- 痛点映射：A1–A5 应能显式映射到意图类别（PRD 中需求-功能 traceability 的依据）。

## 2. 意图 taxonomy v0（八类，多标签）

| 编号 | 意图 | 典型输入 | Jev 判定要点 | 下游管线 |
|------|------|----------|--------------|----------|
| I1 | 素材注入 | 攻略文本/订单截图/链接/机酒信息 | 素材类型、可解析实体清单 | 解析 → 候选池入池 或 锚定落图 |
| I2 | 探索咨询 | "五一去哪看海好""云南怎么玩" | 开放问题、无明确操作对象 | LLM 生成建议 + 候选池积累 |

| I4 | 方案变更 | "去掉这个景点""换家酒店""往后挪一天" | 操作类型（增/删/换/移）+ 目标实体指代消解 | 图操作 + C7 传播 |

## 3. 槽位体系 v0

### 3.1 行程级槽位
- S1 目的地（POI/AOI，支持多级与多目的地）
- S2 日期/天数（允许模糊值："五一前后 5 天"）
- S3 出发地
- S4 预算带（可选）
- S5 同行人结构（人数/构成：老人、儿童等——影响节奏与无障碍判断）
- S6 节奏偏好（休闲/紧凑/深度）
- S7 兴趣标签（自然/人文/美食/亲子……）
- S8 住宿偏好（档位/位置倾向）

### 3.2 实体级槽位
- Event：时间窗、开销（可选，C1）、状态（候选/待定/锁定）
- 锚点（住宿/场站）：锁定状态、关联订单状态
- checklist 项：执行方式档位、相对截止日期、完成状态

### 3.3 阶段流转的槽位门槛（Jev 完整性检查的判定标准）
- 需求明确 → 规划中：S1 必填 + S2 至少有模糊值
- 规划中 → 准备中：图完整——每日有住宿锚点、场站间 Edge 已定、无待定 Event、时间窗无冲突
- 准备中 → READY：checklist 全勾选（含 C10 留空项全部回填或显式跳过）

## 4. 澄清策略 v0

- 缺槽时 Jev 按"阻塞度 × 信息增益"选出**下一个最值得问的槽位**，LLM 包装成自然语言提问。
- 单轮最多问 1–2 个，避免审问感；模糊值合法，不强制精确化。
- 意图低置信度时不强行归类，挂起为异步 HITL 澄清项。

## 5. Jev 决策点清单（与 LLM 分工边界）

| 决策点 | 输入 | 输出 schema | 置信度用途 |
|--------|------|-------------|-----------|
| 意图分类（多标签） | 用户输入 + 当前方案状态 | I1–I8 各标签概率 | 低置信→异步 HITL |
| 阶段判定 | 图状态 + 槽位完成度 | 四阶段判定结果 | 机械检查，达标自动流转（共识 T2） |
| 槽位抽取 | 用户输入 | 槽位名-值对列表 | 低置信槽位不进库，转澄清 |
| 完整性检查 | 图 + 槽位 | 缺失项清单 + 阶段门槛判定 | 驱动澄清问题选择 |
| 实体指代消解 | "这个景点""那家酒店" | 图内实体 ID | 歧义→给候选让用户点选 |
| 澄清问题选择 | 缺失槽位列表 | 下一问槽位 ID | —— |
| 传播半径判定 | 图操作 + 行程语义 | R1/R2/R3（C7） | 低置信→异步 HITL |

LLM 负责：素材内容理解与摘要、建议与理由的自然语言生成、澄清问题的措辞、工具调用参数构造。

## 6. 开放问题裁决记录（全部关闭）

- **T1 ✅**：八类意图无遗漏、无需合并，多标签共存机制确认。补充设计细节（共识）：I5/I6 属"状态变更型"意图，误锁定代价远大于漏识别，其置信度阈值应显著高于 I2/I3 等"信息型"意图——阈值分级写入 Jev schema 设计。
- **T2 ✅**：阶段流转**不需要**用户确认。准备中→READY 是机械检查（checklist 清空即可）；规划中→准备中同理（完整性门槛达标即流转）。阶段判定函数每次输入后自动运行，达标自动流转（降级同理，承 C8）。
- **T3 ✅**：槽位冲突规则 = 后输入优先，但需**显式确认**（如"5 天→7 天"需用户确认后覆盖，不静默）。
- **T4 ✅**：意图 taxonomy 与 A1–A5 的映射将以 traceability 表形式显式写入 PRD（本文 §2 表格即其雏形）。
